# Architectural audit — 2026-07-06 (synthesized)

Three parallel deep audits (Rust core · frontend · Claude/MCP pipeline) over the whole repo,
synthesized and prioritized. File:line refs verified by the auditors at audit time.

---

## TIER 1 — Correctness holes (fix before new features)

### 1. The freeze guarantee has two real bypasses  ⚠️ most important finding
The 🔒 lock is enforced only inside `run_stage`/`self_check_stage` (agent.rs). Confirmed holes:
- **Chat/MCP bypass:** `chat_send` allows `mcp__songsmith` → Claude can call `save_artifact`
  (tools.rs:161 → db.rs:349) which writes straight to the DB with **no freeze check**. "Rewrite the
  lyrics and save" in chat silently replaces frozen sections (and drops the `frozen` flag). The Tauri
  `save_artifact` command (lib.rs:150) is equally unguarded; `revert_artifact` can resurrect
  pre-freeze revisions.
- **Parse-failure hole:** `build_merged_content` (agent.rs:280-301) — if the model output has no
  parseable JSON, the splice branch is skipped and a `{data: null}` revision is saved: frozen
  sections vanish from "current" exactly when the model misbehaves.

**Fix:** enforce at the write boundary — a wrapper around `db::save_artifact` that, when the prior
current artifact has frozen sections, runs `merge_frozen_sections` on the incoming content (all
three entry points: MCP tool, Tauri command, agent). And in `build_merged_content`, when prior has
frozen sections and new data is unparseable → fail the run (or keep prior data), never save null.
(Also LOW: renamed frozen section can duplicate — old re-inserted + renamed rewrite kept.)

### 2. `call_claude` can hang forever, deadlock, and strand state (agent.rs:594-682)
- No timeout; a hung CLI blocks the stage forever and the `inflight` guard (lib.rs:113) blocks
  retries until app restart. **No cancel exists in the UI.**
- stderr is piped but only read after `child.wait()` → classic pipe deadlock if the CLI writes
  >~64KB stderr mid-run. Same pattern in `chat_send` (lib.rs:418).
- No `kill_on_drop` → zombie `claude` processes; `next_line().await?` can propagate before reaping.
- Failed runs leave the stage stuck `in_progress` (set at agent.rs:322, never reset on error).
- `result.is_error`/`subtype` never checked — an error-shaped success gets saved as the artifact.

**Fix:** `tokio::time::timeout` (configurable), `kill_on_drop(true)`, concurrent stderr drain,
reset status on error, check `is_error`, a `cancel_stage` command holding child handles in
AppState (mirror `login_child`). Also add `--max-turns` + disable default tools for pure-gen calls.

### 3. Frontend crash + race (both user-reachable)
- **Rules-of-Hooks violation** `components/Composer.tsx:139-151`: early return before a `useMemo`;
  add/remove the last section → "Rendered more/fewer hooks" crash. One-line fix (hoist the memo).
- **Late-lyrics race** ComposerRoute/compose/Composer.tsx:100-106: chords + lyrics are separate
  queries; `comp.id` is stable, so if chords resolve first the full-song import renders **without
  lyrics for the whole session**. Fix: build `comp` only when both queries settle (or compare a
  content signature, not id).

### 4. Data-integrity races (worse because app + mcp-shim are two processes on one DB)
- **Migration atomicity** db.rs:75-82: the lyric_spec ordinal shift + insert are separate,
  non-transactional, errors swallowed via `let _ =` → a mid-way failure re-shifts ordinals on next
  launch = permanent stage-order corruption. Wrap in a transaction.
- **Artifact version race** db.rs:349-361: read-max-then-insert; concurrent app/shim saves make
  duplicate versions and `current_artifact`'s tie-break arbitrary — which feeds the freeze merge's
  notion of "prior". Fix: single-statement `COALESCE(MAX(version),0)+1` + UNIQUE(stage_id,version).
- No transactions on multi-statement writes (create_song, delete_song); no `busy_timeout` on the
  shim connection ("database is locked" surfaces as raw tool errors); 11 write-then-reload
  `.unwrap()`s in db.rs that panic and can poison the inflight mutex.

## TIER 2 — Architecture debt (schedule soon)

5. **Dual `text`/`data` rendering is hand-mirrored across two languages** (agent.rs:136-249 vs the
   TS editors) with no parity guard; plus the no-freeze run path stores raw fenced-JSON model output
   as `text` while other paths store clean renders (bimodal). Fix: Rust becomes the single renderer
   (`render_artifact_text` command; editors save `data` only), or at minimum golden-file parity
   tests. Related: `save_artifact` accepts arbitrary content — add `validate_content(kind, ...)`.
6. **Skill precedence bug** db.rs:115/399: `seed_skills` re-timestamps builtins every launch and
   selection is `ORDER BY updated_at DESC` → user-*created* skills silently outranked after each
   restart. Fix: update builtins only when body differs; prefer `source='user'` in ordering.
7. **api/mockApi parity is unenforced** (~56 real commands; 3 known mismatches; mock returns
   untyped `any`). Fix: shared `CommandMap` type — drift becomes compile errors.
8. **Artifact `any` epicenter**: 5 ad-hoc `any` parsers + 4 copies of chord-shape coercion. Fix:
   zod per-kind schemas in `lib/artifacts.ts` (zod already a dep, pattern proven in compose/schema).
9. **Prompt-builder fragmentation**: 4 builders; `refine_field` (agent.rs:578) has zero song
   context (no preset/key — off-style suggestions); chat's Ableton preamble duplicated in lib.rs +
   ChatPanel. Fix: one `prompt.rs` context assembler in core.
10. **Business logic in the Tauri layer**: MIDI/chord/Ableton logic in lib.rs:798-1229 (~450 lines,
    untestable, invisible to MCP); structure-section parsing triplicated in lib.rs. Move to core
    (`midi.rs`/`ableton.rs`), register as tools.
11. **agent.rs god-module trajectory** (884 lines, six concerns, duplicate renderer sets at
    :136-249 vs :547-574). Split into engine/render/freeze modules before the next feature.
12. **Per-tick button grids won't scale** (NoteLane/ChordLane): a 48-bar import ≈ 11,500 DOM
    buttons. Fix: CSS gradient gridlines + one pointer-derived hit surface per lane (useSpanDrag
    already proves the math). Related: LyricRow inserts one grid row per lyric line (~720px for a
    full song) — cap/condense; scope `selectedId` per lane.
13. **MCP shim is strictly serial** — a long `run_stage` over MCP blocks everything, trips the
    client timeout, invites retry-races. Spawn per-request or return fast "started" semantics.
    The shim's auth token is generated + advertised but never validated — enforce or delete.

## TIER 3 — Hygiene (batch into a cleanup pass)

14. **Naming collision**: two `Composer` components + "Builder"/"Builder / manage". Rename:
    `components/Composer.tsx` → `SectionChordsEditor`; `compose/Composer.tsx` → `Sketchpad`
    (route/title stay "Composer" for users); tab "Builder / manage" → "Arrange".
15. **Dead code**: ~1,000 LOC never-imported ported engine files (positions, roman-analysis,
    chord-scales, degrees, quality-labels, voicings/push, instruments/*/layout), `BARS`/
    `TOTAL_TICKS` back-compat aliases (zero real importers), `.badge.published`/`.field-chat` CSS,
    dead MCP token, `analyze_reference` mock orphan, stale "128-tick"/YT-fork comments + ChatPanel
    YT copy.
16. **Duplication**: ChordPro parsing in 7 files (→ `lib/music/chordpro.ts`); auto-place algorithm
    twice; three scale-table sets (fold `music/theory.ts` into lib); `deriveSections` lives in a
    component but is imported by lib (layering inversion — move to `lib/music/songSections.ts`);
    copy-pasted draft-editor lifecycle (→ `useArtifactDraft` hook); 10-line lane-label style block
    copy-pasted ×4; SongWorkspace god-component (320 lines → extract StageEditor switch).
17. `parseStoredComposition` doesn't normalize (no sort/overlap/own-totalTicks clamp) — needed
    before Phase 3 persistence; make spans' `totalTicks` param required (silent 128 default).
18. FKs declared but never enforced (`PRAGMA foreign_keys=ON`); row helpers coerce decode errors
    to defaults; setup `expect()` panics instead of a user dialog; `std::mem::forget(database)`
    uncommented.

## Verified GOOD — preserve
- **Single tool registry** (tools.rs) consumed identically by UI/agent/MCP + the mock-parity test.
- **Deterministic freeze splice + `SONGSMITH_MOCK_CLAUDE`** e2e hook — enforcement by code with
  subscription-free proof; extend, don't weaken.
- **Append-only artifact journaling** + ts-rs typed IPC boundary.
- **Pure compose core** (spans/playback/reducer) and the **versioned schema seam** built before
  persistence exists; single IPC choke point (api.ts); disciplined react-query/local-state split.
- **Auth hygiene verified**: every claude spawn strips ANTHROPIC_API_KEY/AUTH_TOKEN.
- Test coverage reality: 9 Rust tests, 0 frontend tests, no frontend test runner. The freeze is the
  best-tested logic; the riskiest untested paths are the migration, versioning, and stream parsing.

## Suggested fix order
1. Freeze write-boundary + parse-failure hole (restores the advertised guarantee)  — small/medium
2. call_claude hardening + cancel + stage-status reset — medium
3. The two frontend bugs (hooks crash, late-lyrics race) — small
4. Migration transaction + atomic versioning + unwrap sweep — small/medium
5. Skill precedence + CommandMap parity + zod artifact schemas — medium
6. Tier-3 cleanup pass (rename, dead code, chordpro/theory dedup) — mechanical
